# Image2Pdf_2.0

把文件夹里的图片批量打包成 PDF。初衷是网上下的 PNG 漫画散图——打包成 PDF 放手机上翻着看更方便。

## 功能

- 支持 `jpg` / `jpeg` / `png` / `bmp`
- **页面按自然顺序排列**：`1, 2, 3, …, 10`，而不是字典序的 `1, 10, 11, 2`
- 可选是否处理下一级子文件夹，两种模式：
  - **所有文件夹到一个文件**：根目录和所有子目录的图片合并进同一个 PDF
  - **每个文件夹到单独文件**：每个有图片的目录各生成一个 PDF，输出到图片目录下、用目录名作文件名
- 可选的重新压缩，由「压缩质量」框决定：

  | 取值 | 行为 |
  | --- | --- |
  | `0` | 不压缩，原图直接写进 PDF（默认，最清晰、体积最大） |
  | `1-99` | 转成 JPG 重压缩，数字即 JPG 质量（有损） |
  | `>=100` | 转成 24bit PNG（无损，速度较慢） |

- 转换在后台线程执行，进度条分「读取 / 转换 / 写入」三个阶段推进并显示当前文件名，可随时取消
- 单张图片读取失败不会中断整个任务，结束后汇总报告哪些图没进 PDF
- 输出文件已存在时会先确认；多个目录产出同名文件时自动改名，不会静默覆盖

## 说明

- PDF 页面尺寸随图片自适应，默认 DPI 72
- 生成 PDF 用的是 [Magick.NET](https://github.com/ImageMagick/ImageMagick)（ImageMagick 的 .NET 封装），**不需要**额外安装 Ghostscript
- 重压缩会在系统临时目录（`%TEMP%\Image2Pdf_<随机号>`）里落盘缓存，无论成功、失败还是中途取消都会清理干净
- 子文件夹模式下若两个目录会产出同名 PDF（例如图片目录本身与某个子目录重名），后一个自动改名为 `名字 (2).pdf`
- **内存占用大致与图片张数成正比**：写多页 PDF 时所有页面必须同时驻留，实测 40 张 2000×2800 约占 700MB。这是所用库的固有代价（不是内存泄漏），想压下来只能分批生成
- 环境：.NET Framework 4.8.1；用 Visual Studio 打开 `Image2Pdf.sln` 直接编译运行
